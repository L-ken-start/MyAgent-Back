# Product

## Register

product

## Users

MyAgent serves developers working inside a local project. They need to inspect files, select concrete code or text, ask contextual questions, review proposed changes, and approve local actions without losing their place in the workspace.

## Product Purpose

MyAgent is a desktop coding agent with a Go runtime and a focused workbench UI. Its primary workflow keeps project content in the main workspace and the agent conversation in a persistent side panel. Selecting content and asking about it must be a first-class action, not a copy-and-paste workaround. Success means a developer can understand, change, and verify a project through one clear, reviewable interaction loop.

## Brand Personality

Calm, professional, focused. The interface should feel trustworthy under sustained use, keep implementation details subordinate to the task, and communicate actions and risks plainly.

## Anti-references

Do not resemble a decorative AI dashboard, a card-heavy SaaS admin template, or a chat app that hides project context behind bubbles. Avoid gratuitous animation, oversized marketing typography, glass effects, excessive status widgets, and visual noise that competes with code and diffs.

## Design Principles

1. Keep the work visible: project content and the agent remain side by side.
2. Make context explicit: selected text, files, ranges, and tool actions are visible and removable before sending.
3. Show consequences before commitment: edits and commands are reviewed at the point of decision.
4. Preserve flow: routine navigation is quiet, fast, and keyboard accessible.
5. Earn complexity: new panels and controls appear only when a proven workflow needs them.

## Accessibility & Inclusion

Target WCAG 2.2 AA contrast and interaction requirements. Every core workflow must be keyboard operable, focus state must remain visible, color cannot be the only carrier of state, and motion must respect reduced-motion preferences.
